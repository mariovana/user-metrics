Auditar Eventos en Mixpanel

Cómo encontrar por tu cuenta eventos duplicados, con nombres malformados o instrumentados dos veces — y cómo saber qué SDK los está mandando.

Las tres propiedades que lo revelan todo

Segment adjunta metadata técnica a cada evento que llega a Mixpanel. Casi cualquier investigación se resuelve con estas tres:

PropiedadQué te diceValores reales en vana
mp_lib Qué SDK envió el evento Segment Actions: analytics.js = web
Segment Actions: analytics-kotlin = Android
event_original_name El nombre que la app envió antes de que Segment lo transformara la clave de todo
path / url Qué pantalla de la web lo emitió /nps, /pay/nps…
Por qué importa event_original_name

El destino Mixpanel (Actions) en Segment construye el nombre de los eventos de pantalla como Viewed {{ name }}. Comparar el nombre final contra el original te dice exactamente en qué punto del pipeline se ensució el nombre — y por lo tanto dónde se arregla.

Para ver qué propiedades trae un evento: Lexicon → Events → clic en el evento → lista de propiedades. O en Insights, al agregar un breakdown, escribe «original» o «lib» en el buscador de propiedades.

1
Lexicon

Ver qué nombres existen

Lexicon es el catálogo de eventos. Sirve para reconocer el problema, no para medirlo. Entra a Data Management → Lexicon → pestaña Events.

  1. Busca Viewed Viewed → aparecen los 23 eventos de doble prefijo de inmediato.
  2. Para sufijos redundantes el buscador no alcanza, porque busca «contiene», no «termina en». Hay dos salidas:
    • Ordenar por nombre (A–Z) y escanear: los duplicados quedan pegados porque comparten prefijo — Viewed Bank Account Details, Viewed Bank Account Info, Viewed Bank Account Information, Viewed Bank Account Viewed. Con 177 eventos Viewed * es tedioso, pero funciona.
    • Exportar Lexicon a CSV y filtrar en Google Sheets con regex — más rápido y repetible.

Fórmulas de Sheets, con la columna A = nombre del evento

# cualquier palabra repetida (atrapa "Viewed Viewed", "Wallet … Wallet")
=REGEXMATCH(A2, "\b(\w+)\b.*\b\1\b")

# termina en verbo de visualización → sufijo redundante
=REGEXMATCH(A2, "(Viewed|Displayed|Shown)$")

# espacios dobles (atrapa "Viewed Bank Ticket  Details", 359 k/mes)
=REGEXMATCH(A2, "  ")

# mismo nombre con distinto casing → duplicado invisible
=COUNTIF(ARRAYFORMULA(LOWER($A$2:$A$600)), LOWER(A2)) > 1

3
Interpretar

¿Bug de pipeline o problema de convención?

Este es el paso que la mayoría se salta, y es el que decide quién tiene que arreglarlo. Compara el nombre final contra event_original_name:

Si…SignificaDónde se arregla
final = "Viewed " + original pasó por page() / screen() y el mapping le puso el prefijo Segment (Insert Function) + la app que manda el nombre pre-formateado
final = original exacto fue un track(); Segment no lo tocó el código de la app — es convención de naming

Los dos casos, lado a lado, con datos reales

event_original_nameEvento finalSDKVeredicto
VRM Viewed Viewed VRM Viewed web bug de pipeline
Notification Inbox Viewed Notification Inbox Android + web correcto
Notification Inbox Viewed Notification Inbox Viewed web doble instrumentación
Hallazgo nuevo que salió con este método

La pantalla del inbox de notificaciones está instrumentada dos veces desde la web, con dos nombres distintos:

analytics.page("Notification Inbox") → Viewed Notification Inbox — 90,625 web + 617,809 Android
analytics.track("Notification Inbox Viewed") → Notification Inbox Viewed — 775,022, solo web

Son ~1.48 M eventos/mes para una sola vista de pantalla, contados dos veces con nombres distintos. Android solo emite el correcto. Acción: la web elimina el track() redundante y se queda con page().

4
Events · stream crudo

Localizar la línea de código

Para cerrar la investigación y darle al equipo de desarrollo la ubicación exacta:

  1. Abre el explorador de Events (el stream de eventos crudos en el nav lateral).
  2. Filtra por el nombre del evento sospechoso.
  3. Abre una ocurrencia individual y revisa sus propiedades.
  4. Las propiedades path y url te dicen la ruta exacta de la web que lo emitió — eso es lo que le pasas al equipo web.

Ejemplo: el evento huérfano Viewed (3,995/mes) trae path = /nps y /pay/nps → son esas dos páginas las que llaman analytics.page() sin nombre.

La receta, para cualquier duplicado

Este flujo no es solo para Viewed: sirve para casing, typos, espacios dobles y cualquier familia de eventos sospechosa.

01
Sospecha — detecta el patrón en Lexicon: buscar, ordenar A–Z, o exportar a Sheets con regex.
02
Mide — Insights con filtro contains sobre Event Name, breakdown por Event Name.
03
Atribuye — agrega breakdown por mp_lib (qué SDK) y source_app / product_context (qué app y producto).
04
Diagnostica — agrega breakdown por event_original_name y compáralo con el nombre final: ahí se ve si el problema es del pipeline de Segment o del código de la app.
05
Localiza — explorador de Events → propiedades path / url del evento crudo.
06
Documenta — nombre canónico, dónde se arregla, y cómo verificar que el volumen del evento malo cae a cero.
